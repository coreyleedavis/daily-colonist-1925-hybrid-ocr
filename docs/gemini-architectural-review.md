# Phase 2 Hybrid OCR Pipeline: Architectural Review

> **Author note:** This technical review was generated by Google Gemini. It serves as a devil's-advocate analysis of the Phase 2 hybrid pipeline, evaluating the system architecture against established data-processing and digital-preservation practices. Reproduced as received, for transparency, alongside the project's own documentation.

An analysis of the Phase 2 hybrid pipeline shows a structured approach to integrating disparate optical character recognition outputs. The architecture demonstrates sound engineering principles, particularly regarding data retention and auditability.

Below is an evaluation of the current design, separating technical strengths from areas requiring optimization.

## Architectural strengths

- **Traceability and provenance.** The sidecar file ensures every word carries one of twelve provenance classes. It avoids the silent data loss typical of standard post-OCR correction pipelines and allows for precise corpus-level auditing.
- **Scale-adaptive clustering.** Utilizing the local median word height for grouping logic (0.6× for lines, 1.5×/2.0× for orphans) rather than fixed pixel thresholds allows the system to process multi-format newspaper layouts without manual reconfiguration per page.
- **Non-destructive ambiguity handling.** Pushing undecidable disagreements (the `residual-alt` class) to the index as a search-time alternative is an optimal use of the search backend. It delegates final resolution to the user's query rather than forcing an arbitrary pipeline decision.
- **Conservative destructive actions.** The deduplication logic requiring exact containment or verified hyphen-stubs minimizes the risk of deleting valid content. Requiring external-dictionary validation before executing dehyphenation across block seams improves on naive assumptions.

## Areas for improvement

### 1. Alignment algorithm inefficiencies

Python's `difflib.SequenceMatcher` uses a gestalt pattern-matching approach that scales quadratically. This inefficiency necessitates the `ALIGN_GUARD` limit. Implementing a standard edit-distance algorithm (such as Levenshtein distance via a C-extension library like `edlib`, or Needleman-Wunsch) provides character alignment with predictable O(N × M) performance. These algorithms are optimized specifically for the substitution, insertion, and deletion error profiles characteristic of OCR output.

### 2. Dictionary baseline limitations

The `vlm-dict` and `tess-dict` routing rules rely entirely on standard modern dictionaries. A 1925 Canadian newspaper contains specific regional vocabulary, historical proper nouns, and localized terminology absent from standard lists. Integrating a historical gazetteer or a curated local vocabulary list would mitigate routing errors where a correct generative reading of a local noun is overwritten by a modern Tesseract misread.

### 3. Center-point containment vulnerability

Assigning Tesseract words to generative text blocks via center-point containment assumes an orthogonal layout. If the microfilm scans exhibit skew, page curvature, or warping, the center points of edge words can shift into adjacent bounding boxes. Evaluating Intersection over Union (IoU) or polygon-based containment would increase system robustness against scan distortion.

### 4. Dependency on block-level output

The geometry estimation (`interp`) is necessary because the current generative model provides only block-level coordinates. Upgrading the generative side of the pipeline to a vision-language model or structured-extraction approach capable of native line-level or word-level geometry would reduce the volume of words relying on estimated positions and decrease the need for interpolation logic.

### 5. Confidence metrics for orphan clusters

The `orphan_verdict` function uses the median confidence of a cluster to determine retention. While the median is robust against single-word outliers, it treats all words equally regardless of length. A weighted average based on word length would provide a more accurate representation of the region's overall readability.
